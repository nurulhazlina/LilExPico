Sending Data to a Live Dashboard

Your board posts every sensor reading to Google Sheets over WiFi. A web dashboard reads the sheet and updates itself every few seconds — from anywhere, with no server to run.

How it works

Three hops connect the board to your browser. You do not write any of the middle parts — Google does.

Data makes a round trip: the board uploads readings, Google stores them, and the dashboard downloads them for display. This pattern is used in real IoT products.

Why not send data straight to the browser? A browser cannot open a direct connection to a Pico on a different WiFi network — both sides are behind a router. The spreadsheet is a shared notice board: the Pico writes to it and the browser reads from it, and neither side needs to know the other’s address.

What you need

  • Already on Pico main.py — the full sensor program from earlier activities
  • Already on Pico adapter.py — the display-field helpers
  • Already on Pico All sensor driver files (bme280.py, ags10.py, and the rest)
  • New file wifi_reporter.py — handles WiFi connection and HTTP POST
  • New file main_dashboard.py — same as main.py with three WiFi additions
  • You edit this config.py — put your WiFi name, password and Apps Script URL here
  • Deploy once LilEx5_AppsScript.js — paste this into Google Apps Script

You also need a Google account to create the Apps Script project. It is free; no billing is required.

Step by step

Deploy the Apps Script

This is the piece that lives on Google’s servers and talks to both the board and the dashboard. You only do this once.

  1. Go to script.google.com and click New project.
  2. Delete everything in the editor and paste in the whole contents of LilEx5_AppsScript.js.
  3. Click Deploy → New deployment.
  4. Click the gear icon next to Type and choose Web app.
  5. Set Execute as to Me and Who has access to Anyone.
  6. Click Deploy, approve the permissions prompt, then copy the Web app URL — it ends with /exec. Keep it open; you need it in Step 2.
Copy the /exec URL, not the /dev URL The Manage deployments screen shows two addresses. Use the one ending in /exec — that is the one the board and dashboard both need. The one ending in /dev only works when you are logged in to Google.

Edit config.py

Open config.py in Thonny. Add these four lines, or change them if they are already there. Use your own WiFi name, password, and the URL you just copied.

# WiFi and dashboard settings — edit these four lines
WIFI_SSID          = "YourNetworkName"      # your WiFi name
WIFI_PASS          = "YourPassword"         # your WiFi password
APPS_SCRIPT_URL    = "https://script.google.com/macros/s/YOUR_ID/exec"
REPORT_INTERVAL_MS = 5000                  # post every 5 seconds
Each student uses their own WiFi settings config.py is the only file that differs between boards. Save it to the Pico (not just to your computer) using File → Save as… → Raspberry Pi Pico in Thonny.

Upload the new files to your Pico

In Thonny, open each file from the downloaded folder and save it to the Pico using File → Save as… → Raspberry Pi Pico.

  • wifi_reporter.py
  • main_dashboard.py

Both files should now appear in the Raspberry Pi Pico panel on the left of Thonny.

Do not overwrite main.py main_dashboard.py is a separate file. Your original main.py stays on the Pico unchanged and still runs the same way when you open it.

Run main_dashboard.py

In Thonny, open main_dashboard.py from the Pico panel and press the green Run button (or F5).

Watch the Shell at the bottom. You should see something like this:

MPY: soft reboot
[WiFi] Connecting to YourNetworkName...
[WiFi] Connected. IP: 192.168.1.42
[WiFi] POST 200 OK — 20 fields sent
[WiFi] POST 200 OK — 20 fields sent

Each POST 200 OK line means one row has been added to the Google Sheet. If you see it repeating every five seconds, the board is working correctly.

If you see no module named 'network' Your Pico is running standard MicroPython firmware, not the Pico W version. Only Pico W firmware includes WiFi support. Flash the Pico W firmware from micropython.org/download/RPI_PICO_W/: hold BOOTSEL, plug in the USB cable, then drag the .uf2 file onto the RPI-RP2 drive that appears. Then re-upload all your files.

Open the dashboard and watch the data arrive

Open LilEx5_Dashboard4.html in a browser. Every five seconds it fetches the latest row from the sheet and updates all the tiles and graphs.

▶ Open the live dashboard All six sensors — environment, motion, magnetic field and the four analogue channels — shown live. The graphs grow as the board keeps sending.

Open dashboard

To check the raw data, open your Google Sheet. It was created automatically when the first POST arrived and has a SensorData tab with one row per reading.

What each file does

FileLives onWhat it does
config.pyPico Your WiFi name, password, Apps Script URL and posting interval. The only file that differs between students.
wifi_reporter.pyPico The WiFiReporter class. Connects to WiFi, bundles all sensor readings into a JSON message, POSTs it to the Apps Script URL, and rate-limits itself so it does not flood the network.
main_dashboard.pyPico Identical to main.py with three additions: imports WiFiReporter, connects on startup, and calls reporter.maybe_send(data) once per loop. The OLED, buttons and all sensors work exactly as before.
LilEx5_AppsScript.jsGoogle Apps Script doPost() receives data from the Pico and writes a row to the sheet. doGet() reads the latest row and returns it to the dashboard.
LilEx5_Dashboard4.htmlYour browser A self-contained web page. Polls the Apps Script every 5 seconds, updates 20 reading tiles, and draws live graphs for all sensor groups.

What to look for on the dashboard

SectionSensorTry this
EnvironmentBME280 Breathe on the board — temperature and humidity both rise within a few seconds.
EnvironmentAGS10 Hold the board near a marker or hand sanitiser — the TVOC value climbs.
EnvironmentVCNL36821S Move your hand closer to the board — the proximity count increases.
MotionBMI323 Pick the board up and tilt it — the accelerometer X, Y, Z lines separate on the graph.
Magnetic fieldQMC6309 Bring a fridge magnet near the board — watch which axis jumps.
Analogue inputsADS1115 Connect a sensor or potentiometer to the H3 connector — the matching channel voltage moves.

Troubleshooting

What you seeLikely causeFix
ImportError: no module named 'network' Standard Pico firmware, not Pico W firmware Flash the Pico W firmware. Hold BOOTSEL, plug USB, drag the .uf2 onto the RPI-RP2 drive. Then re-upload all your files.
Hangs at [WiFi] Connecting… Wrong SSID or password, or the network is 5 GHz (Pico W only supports 2.4 GHz) Double-check WIFI_SSID and WIFI_PASS in config.py — both are case-sensitive. Ask if the classroom network is 2.4 GHz.
POST error code (302, 400, 403…) Wrong Apps Script URL or deployment not set to Anyone In Apps Script go to Deploy → Manage deployments, copy the URL ending in /exec, and confirm Who has access is Anyone.
Dashboard shows “Offline” or -- everywhere The API_URL in LilEx5_Dashboard4.html has not been updated, or the Pico has not sent its first reading yet Check the API_URL constant near the top of the dashboard file matches your /exec address. Wait for a POST 200 OK in Thonny, then refresh.
Shell shows POST 200 OK but the sheet stays empty The sheet tab is not named SensorData Rename the first tab in your Google Sheet to exactly SensorData (case matters).

Going further

TaskWhat to try
Change how often the board posts Edit REPORT_INTERVAL_MS in config.py. 1000 is once a second; 60000 is once a minute.
Keep history in the dashboard Find the Samples each graph keeps box at the bottom of the dashboard and type a number — for example 60 to show the last five minutes.
View from your phone Open LilEx5_Dashboard4.html on a phone. Or upload the file to any web host — the Apps Script URL is already public.
Chart in Google Sheets Select a data column in the SensorData tab and insert a chart. It updates live as new rows arrive.
Two boards, one sheet Have two students run main_dashboard.py with the same Apps Script URL. Both write to the same sheet; the dashboard shows the most recent reading.
Export to CSV In Google Sheets click File → Download → Comma-separated values for a snapshot of everything the board has ever sent.
